*** Viva Wallet Smart Checkout Changelog ***
2026-09-17 - version 2.1.1
Fix: Add optional Color parameter for Smart Checkout branding.

* ENHANCEMENT
  - Added "Color" configuration field (hex color code) to the plugin admin settings.
  - Server-side validation via HexColor backend model ensures only valid 3/6 character hex values are saved.
  - Strips '#' prefix automatically; stores raw hex for direct URL use.
  - When configured, appends &color={ColorCode} to the Smart Checkout redirect URL.
  - Fully optional: if left empty, the redirect URL is unchanged and Viva's default branding applies.
2026-09-17 - version 2.1.0
Feature: Native online refund integration with Viva Wallet API.

* NEW FEATURE
  - Enabled online refund capabilities ($_canRefund = true, $_canRefundInvoicePartial = true).
  - Implemented PaymentMethod::refund() to support online Credit Memos directly from the Magento Admin backend.
  - Implemented VivaApiClient::refundTransaction() sending DELETE requests with Basic Authentication to Viva's /api/transactions/{transactionId} endpoint.
  - Supports full and partial refunds with multi-store credential resolution.
  - Automatically records the Viva refund transaction ID on the Magento payment and credit memo.
  
2026-09-15 - version 2.0.3
Fix: Prevent premature order cancellation on failed payment callbacks to allow retries.

* BUG FIX
  - Prevented immediate order cancellation and restocking upon failed payment callbacks.
  - Replaced cancellation in processFailedPayment() with an order status history comment, keeping the order in pending_payment state.
  - Allows customers to retry payments using the same Viva OrderCode (e.g. after correcting card details or using browser navigation) without causing invoice generation failure due to previously cancelled items.
  - Properly handled configured order status mapping for complete state in processSuccessfulPayment().
  - Abandoned unpaid orders continue to be automatically cancelled by Magento's configured order lifetime cron.

2026-05-18 - version 2.0.2
Fix: Automatic invoice generation and paid status on successful payment callbacks.

* BUG FIX
  - Fixed configuration to use standard Magento payment_action "authorize_capture" instead of invalid "true".
  - Explicitly generate, register, and save invoices via Magento's InvoiceService and TransactionFactory during successful payment callbacks to guarantee generation.
  - Automatically email the generated invoice to the customer via InvoiceSender.
  - Added $_canCapture and $_canCapturePartial properties to PaymentMethod class.
  - This allows Magento to automatically generate and mark invoices as paid (captured) during the payment capture callback processing (registerCaptureNotification), eliminating the need for manual backoffice invoice approval.

2026-05-13 - version 2.0.1
Fix: 401 Unauthorized on transaction verification in multi-store environments.

* BUG FIX
  - VivaApiClient now accepts an explicit storeId to read Merchant ID, API Key,
    and all other config values from the correct store scope.
  - Callback controller passes $order->getStoreId() to verifyTransaction(),
    ensuring the callback authenticates with the credentials of the store that
    created the order — not the default store.
  - PaymentMethod passes $order->getStoreId() to createPaymentOrder() for
    consistent store-scoped config during order creation.


2026-04-02 - version 2.0.0
Major security and architecture refactor for Magento 2.4.8-p3 / PHP 8.4 compatibility.

* SECURITY
  - Removed global override of Magento CookieManagerInterface (di.xml preference)
  - Removed global override of Magento SessionManagerInterface (di.xml preference)
  - Re-enabled SSL verification on all outgoing Viva Wallet API calls (CURLOPT_SSL_VERIFYPEER)
  - Removed CSRF bypass (validateForCsrf returning true) from callback controller
  - Implemented transaction verification via Viva API as callback authentication mechanism
  - Eliminated raw exception messages exposed to customers; replaced with safe generic messages
  - Added htmlspecialchars escaping on all dynamic output in redirect form HTML
  - Added idempotent callback processing to prevent duplicate payment captures
  - Added input validation for callback request parameters

* ARCHITECTURE
  - Created Service/VivaApiClient.php — centralized Viva Wallet API communication
  - Created Service/OrderProcessor.php — payment callback business logic and order state transitions
  - Replaced all direct curl_* calls with Magento\Framework\HTTP\Client\Curl via CurlFactory
  - Replaced all ObjectManager usage with constructor dependency injection
  - Removed direct echo output in controllers; using Result\Raw and Result\Redirect
  - Controllers refactored to thin delegation pattern (Start, Callback)
  - PaymentMethod model delegates API calls to VivaApiClient service
  - PaymentMethod model delegates record persistence to VivaPaymentsFactory

* DELETED FILES
  - Session/SessionManager.php (dangerous global session override with ObjectManager usage)
  - Stdlib/Cookie/CookieManager.php (dangerous global cookie override, obsolete SameSite hack)
  - Validator/SameSite.php (obsolete user-agent based SameSite detection)
  - Setup/InstallSchema.php (replaced by declarative schema)

* NEW FILES
  - Service/VivaApiClient.php (Viva API client service)
  - Service/OrderProcessor.php (payment processing service)
  - etc/db_schema.xml (declarative schema for vivapayments_data table)
  - etc/db_schema_whitelist.json (schema whitelist)

* MAGENTO COMPATIBILITY
  - Added declare(strict_types=1) to all PHP files
  - Controllers now implement HttpGetActionInterface instead of extending deprecated Action class
  - Migrated from legacy InstallSchema to declarative db_schema.xml
  - Removed setup_version/schema_version from module.xml (declarative schema)
  - Added module sequence dependencies (Magento_Payment, Magento_Sales, Magento_Checkout, Magento_Store)
  - Fixed module name casing in routes.xml (Ced_Vivapayments → Ced_VivaPayments)
  - Fixed schemaLocation URIs to use urn: format across XML config files

* PHP 8.4 COMPATIBILITY
  - Removed PHP 5.x version checks (version_compare with PHP_VERSION)
  - Removed Magento 2.3.5 version-specific code branches
  - Added typed properties throughout
  - Added return type declarations
  - Replaced rand() with random_int()

* BUG FIXES
  - Fixed inverted null-check logic in order loading (!$order && $order->getId() → proper null safety)
  - Fixed Collection class name (was incorrectly named VivaPayments instead of Collection)
  - Set $_canRefund = false (was true with no implementation)

* CODE QUALITY
  - Replaced generic Exception throws with LocalizedException and NoSuchEntityException
  - Changed properties from protected to private where inheritance is not required
  - Removed dead code (TmSecureKey variable, unused session/locale dependencies)
  - Removed copy-paste comment remnants (Coinbase, hellaspay references)
  - Used class constants for currency map, language list, and config paths
  - Added PSR-3 logging throughout for internal diagnostics
  - Normalized file formatting and final newlines
